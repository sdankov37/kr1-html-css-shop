## Работа №13 — доступность

### 1. Изображения и alt

| Где                           | alt                                                          |
| ----------------------------- | ------------------------------------------------------------ |
| `milk.jpg` в hero (декор)     | `""` (пустой — изображение не несёт смысла)                  |
| карточки в каталоге / главной | описательный: «Бутылка молока «Простоквашино» 3,2%»          |
| галерея на странице товара    | разные ракурсы: «вид спереди», «вид сбоку», «крупным планом» |

У всех `<img>` заданы `width`/`height` — Lighthouse не ругается на CLS.

### 2. ARIA только там, где нужно

**Используется:**

- `aria-label="Основная навигация"` на `<nav>` — отличает от breadcrumbs;
- `aria-label="Хлебные крошки"` на `<nav>` — второе меню;
- `aria-current="page"` на активной ссылке меню и в крошках — сообщает «текущая страница»;
- `aria-label="Наверх"` на кнопке со стрелкой — текст «↑» скринридер не прочитает осмысленно;
- `aria-label="Подробнее о товаре X"` на кнопках «Подробнее» — иначе все 6 ссылок читаются одинаково;
- `role="img"` + `aria-label="Оценка 5 из 5"` на рейтинге из звёзд — звёзды не читаются как символы;
- `aria-describedby="phone-hint"` связывает поле телефона с подсказкой о формате;
- `aria-label="Список товаров"` на `<section>` без заголовка — чтобы стал landmark.

**Не используется (специально):**

- нет `role="navigation"` — `<nav>` уже его даёт;
- нет `aria-required` — `<input required>` уже экспонируется как `required`;
- нет `aria-hidden` на иконках, если рядом есть текст;
- нет `tabindex` — навигация работает в естественном порядке;
- нет `aria-label` на `<aside>` в фильтрах — там уже есть `<h2>Фильтры`, дублировать не нужно.

### 3. Контраст и фокус

- основной зелёный затемнён до `#157347` (было `#009B3A`) — контраст с белым текстом ≥ 4.5:1;
- приглушённый текст затемнён до `#5c5c5c` — ≥ 4.8:1 на фоне;
- звёзды рейтинга `#92400e` — ≥ 5.8:1 на белом;
- `:focus-visible` с `outline: 3px solid` — заметный фокус у всех интерактивных элементов;
- `prefers-reduced-motion` уважается.

### 4. Skip-link

Сверху страницы — `<a class="skip-link" href="#main">Перейти к содержимому</a>`.
Появляется по Tab. Уводит фокус сразу в `<main id="main">`.

### 5. Нативные элементы вместо ARIA

- FAQ на `<details>/<summary>` — работает без JS и без ARIA;
- таблица на `<table>` с `<caption>`, `<th scope="col">`;
- форма с `<label for>` — каждый input связан со своим label;
- `<nav>`, `<main>`, `<aside>`, `<article>` — семантические теги.

## Как выполнить Lighthouse-аудит

1. Открыть `index.html` в Chrome (лучше через Live Server: `http://localhost:5500`).
2. `F12` → вкладка **Lighthouse**.
3. Настройки:
   - **Mode**: Navigation
   - **Device**: Mobile
   - **Categories**: только **Accessibility** (для работы №13)
4. Нажать **Analyze page load**.
5. Когда отчёт появится:
   - сделать скриншот блока со счётом и списком аудитов **или**
   - нажать ⋮ → **Save as HTML**.
6. Сохранить файл в папку **`lighthouse/`**:
   - `lighthouse/a11y-index.html` (или `.png`)
   - повторить для `catalog.html`, `product.html`, `order.html`, `contacts.html`
7. Сделать коммит:
   ```bash
   git add lighthouse/
   git commit -m "Работа 13: Lighthouse accessibility report"
   git push
   ```

```

**Ожидаемый результат**: 95–100 по Accessibility на всех страницах.

Если Lighthouse подсветит что-то — типичные причины:

- `image-alt` — где-то забыт `alt`;
- `color-contrast` — новый цвет, не прошедший AA;
- `label` — поле без label.

## Проверить вручную

- `Tab` по странице — фокус виден, skip-link появляется первым;
- `Tab` в меню — активная ссылка объявляется как «текущая страница»;
- скринридер (NVDA или VoiceOver) читает рейтинг как «Оценка 5 из 5»;
- кнопки «Подробнее» в каталоге читаются по-разному: «Подробнее о товаре Молоко…» и т.д.
```
